### 1. 最終結論

TranslationLossとDeepGrammarを別々に改善して後から接続する方針は採用しない。両者を次の一つの計算体系として再設計する。

~~~text
Unified Geometric DeepGrammar
  = lossless source substrate
  + unified syntax hypergraph
  + profile-specific semantic validators
  + mixed-curvature proposal geometry
  + discrete-continuous mutual distillation

Canonical TranslationLoss
  = source obligation
  + target correspondence
  + typed preservation defect
  + verifier receipt
  + recoverability and residual
~~~

自然言語とprogramを最上位で二分しない。英語、日本語、Rust、C/C++、TypeScript、数式、Markdown、SQL、shell、JSON、doc comment、template literalを同じsource-span、token lattice、packed derivation、binding、scope、dependency、control、effect、discourse relationを持つ共通基質へ収容する。

ただしsemantic acceptanceは分離する。programの型、実行効果、ABI、未定義動作と、自然言語の発話行為、省略、照応、語用論を同じvalidatorへ潰さない。共通化するのはsource、syntax relation、candidate、geometry、provenanceであり、意味検証はGrammarProfile別に行う。

非ユークリッド幾何は意味の真理機械ではない。階層、方向、cycle、異種graph対応を探索するproposal engineである。continuous candidateは必ずdiscrete validatorへ戻り、receiptを持たないcandidateはcanonical parseにもcanonical TranslationLossにも入らない。

TLV3 runtimeは改善されているが、source/retained/introducedの個数を次の式へ入れる。

~~~text
ceil(100 × (lost + introduced) / max(source, 1))
~~~

これは個数保存率としてauditableだが、意味保存率ではない。同数の構造が意味反転しても低lossになり、正しい詳細化でもintroducedが増えると高lossになる。

#### 2.4 現行non-Euclidean / distillation

v6.3.0には2次元Poincaré shadowとtransition_geometry名称の実装があるが、次の制約がある。

- 座標が既存TL平均、contradiction、outputability等から作られ、TL再測定へ使うと循環する。
- Poincaré proxyは対称で、forward/reverse lossを表さない。
- runtimeはpromotion certificateへ常にNoneを渡すためsearchへ接続されない。
- ContinuousSearchShadowは固定priority sortingで、manifold optimizationではない。
- internal candidateはartifact candidate selectionへ寄与しない。

したがって名称上のgeometryとproduction semantic geometryを区別する。

### 3. TranslationLossの起源と五つの記号厳密性regime

内部史ではTranslationLossは2026-02-28のHTLFで、表現間変換によりstructure、context、qualiaが失われる問題として明示された。初期値は定性的見積もりであり、実験校正前提だった。翌日のKCSでdesignからcodeへのtranslationへ拡張された。

現在の五分類は次のように扱う。

1. 数学・論理
2. program
3. 自然言語
4. 創作物
5. その他の行為全般

これはloss componentでも固定weightでもない。記号厳密性を直観的に分類し、保存義務、許容同値関係、validator、abstention条件を選択する**MeasurementRegime**である。

| regime | 主な保存対象 | 主なvalidator |
| --- | --- | --- |
| 数学・論理 | 公理系、量化、証明義務、反例、同値性 | proof assistant、SMT、model checker |
| program | 型、挙動、state transition、ABI、副作用 | compiler、tests、runtime、refinement |
| 自然言語 | scope、modality、discourse、coreference、ambiguity | symbolic parser、semantic graph、NLI、人間評価 |
| 創作物 | constraint、構造、意図、質感、複数許容解 | constraint audit、pairwise review、provenance |
| 行為全般 | Authority、scope、state delta、causal result、reversibility | Authority kernel、execution receipt、state observation |

regimeはmulti-labelである。自然言語中の数式、program内のcomment、創作物を生成するcode、行為を依頼する自然言語は複数regimeを同時に持つ。

行為は表現変換だけではないため、内部型を分ける。

~~~text
ProjectionLoss      表現間で失われたもの
RealizationLoss     計画から実行へ移す際の損失
OutcomeDeviation    実行結果と要求結果の差
AuthorityViolation  許可境界違反。loss値ではなくhard gate
~~~

### 4. 初期統合案

初期案は次の三本柱だった。

1. 自然言語とprogramを共通syntax substrateへ統合する。
2. syntax/meaning graphをnon-Euclidean spaceへ埋め込み、平坦な距離より高密度に関係を探索する。
3. discrete forestとcontinuous geometryを交互に蒸留し、lossの高い箇所を再parse、別profile、別semantic viewへbackflowする。

この方向自体は採用する。ただし以下の敵対的監査により、単一manifold、scalar loss、geometry-driven acceptance、自然言語/program完全同一化は棄却する。

### 5. ポスドク視点の敵対的監査

#### 5.1 Geometryは意味を定義しない

embeddingは与えられたrelationを圧縮する。元relationがheuristicなら、曲率を導入してもheuristicを美しい座標へ洗浄するだけである。geometryは意味の根拠ではなく、対応候補探索に限定する。

#### 5.2 通常のRiemann距離は対称

TranslationLossはA→BとB→Aが異なる。Poincaréを含む通常のRiemann距離だけでは方向損失を表せない。Finsler、directed quasi-distance、typed forward/reverse witnessが必要である。

#### 5.3 距離でないdefectがある

Dropped、Contradicted、IntroducedWithoutSource、Unknown、Incomparableは単なる遠さではない。一個のscalarへ圧縮すると、critical defectが平均で消える。

#### 5.4 自然言語とprogramは同一semanticsではない

共通syntax relationは作れるが、programはexecution、type、effect、environmentを持ち、自然言語はspeech act、pragmatics、social contextを持つ。同じacceptance ruleはcategory errorになる。

#### 5.5 CFGだけでは閉じない

自然言語のagreement、long-distance dependency、ellipsisと、programのtypedef、macro、type-driven resolutionはいずれもsurface CFGだけでは閉じない。packed forest上のtyped constraint graphが必要である。

#### 5.6 完全parserという語は過大

全自然言語、全program、全文脈を正しく理解するparserは検証不能である。完全性はsource totality、grammar-profile coverage、ambiguity retention、backend revisionへ限定する。

#### 5.7 mixed document境界は一意でない

code fence、comment、string、quotation、formula、path、commandは複数profileに見える。hard classifierではなくRegion/Dialect Latticeが必要である。

#### 5.8 座標は非識別

embedding座標は回転、反転、isometry、初期値で変わる。raw coordinateをevidenceにせず、revision-bound relational distortion、neighbor recall、transport residualを記録する。

#### 5.9 曲率選択もheuristicになりうる

すべてをhyperbolicへ入れるのはEuclidean固定と同じ誤りである。sequence、tree、cycle、directed relationをmixed-curvature productへ分け、Euclidean baselineとのablationを必須にする。

#### 5.10 continuous feedbackは自己確認loopを作る

geometry proposalを次epochの教師として無条件採用すると、誤ったclusterが自己強化される。discrete external validatorを通ったedgeだけを次epochのanchorにできる。

#### 5.11 roundtripは意味同値の十分条件ではない

encode/decodeが元surfaceへ戻っても、閉じた誤体系内で安定しているだけかもしれない。independent semantic view、counterexample、compiler/runtime、人間評価が必要である。

#### 5.12 Gromov-Wasserstein couplingはsource anchorではない

soft couplingは異種graph対応候補を与えるが、一対一対応、因果、同義性を証明しない。coupling mass leakageとmany-to-many correspondenceを保持する。

#### 5.13 calibration dataがconstructを決める

gold labelが曖昧なら0〜100を学習してもconstruct validityは得られない。regime、stage、direction、language、backend、defect kindごとにcalibration cohortを分ける。

#### 5.14 Unknownを最大lossへ潰してはならない

fail-closed execution policyとsemantic magnitudeは別である。UnknownはUnknownのまま保持し、危険actionだけをrisk-adaptiveに閉じる。

#### 5.15 GPUはsemantic ownerになれない

parallel distance、transport、candidate scoreはGPU向きだが、floating-point drift、device loss、partial completionがある。CPU reference pathとdiscrete finalist validationが必要である。

#### 5.16 Authority汚染

comment、quote、fixture、assistant summary、parser補完subjectからGrantが生成される危険がある。Authority sourceはhostが境界付けたuser instruction spanだけとする。

#### 5.17 resource explosion

scannerless generalized parse、SPPF、multi-profile、mixed geometry、GWを同時に無制限実行すると計算量が破綻する。ParseBudget、forest cap、epoch cap、coupling cap、typed truncationが必要である。

#### 5.18 evaluation leakage

同じfixtureをgeometry selection、threshold tuning、final evaluationに使うと性能が偽装される。train/calibration/holdout/adversarial setをrevision-boundで分離する。

### 6. 監査による最終修正

敵対的監査を受け、最終設計は次の原則へ修正する。

- canonical ownerをgeometryではなくDiscrete Anchor + Validator Receiptにする。
- TranslationLossをscalarからProjectionDefectGraphへ変更する。
- geometryはmixed-curvature proposal shadowに限定する。
- natural/program binary splitを廃止するが、GrammarProfile別semanticsを保持する。
- discrete→continuous→discreteの各境界にtyped receiptを置く。
- accepted、rejected、NeedsEvidence、Unavailable、Incomparableを全て保存する。
- geometry residualからgrammarやthresholdをsession内自動更新しない。
- 0〜100が必要な場合もcohort-specific empirical riskのadvisory viewに限定する。
- Program IR、Output、Authorityまでsource span lineageを貫通させる。

### 8. 自然言語とprogramを二分しない共通基質

#### 8.1 共通関係

- source span、delimiter、whitespace、comment、quotation
- token/morpheme/operator segmentation
- containment、sequence、dependency、binding、scope
- implicit node、ellipsis、macro expansion、generated node
- name/reference resolution
- malformed input、error recovery、incremental edit
- surfaceからsemantic viewへのlowering

#### 8.2 GrammarProfile feature

NaturalまたはProgramというtop-level enumを使わず、次のfeatureを組み合わせる。

- OpenLexicon / ClosedLexicon / GeneratedLexicon
- ExecutableEffects / DenotationalSemantics / PragmaticActs
- MacroExpansion / ContextSensitiveConstraints / LayoutSensitive
- AmbiguousDerivation / DeterministicDerivation
- EmbeddedDialect / BidirectionalGeneration
- TypeAndOwnership / DiscourseAndCoreference

一つのspanは複数profile candidateを持てる。

#### 8.3 禁止するcollapse

- program実行可能性をsurface likenessから推定しない
- speech actからMutationAuthorityを生成しない
- comment中の命令をhost-user instructionへ昇格しない
- macro-expanded tokenをuser-authored byteと同一視しない
- parser confidenceをcompiler/runtime evidenceへ昇格しない
- geometry近傍をgrammar acceptanceへ昇格しない

### 9. 完全性contract

1. Source totality: 全byte、Unicode、whitespace、comment、quote、formulaをanchorする。
2. Region totality: 全spanに一個以上のprofile candidateまたはUnknownRegionを持たせる。
3. Token totality: competing segmentationをlatticeへ保持する。
4. Syntactic totality: malformed inputでもCST、error node、unparsed spanを返す。
5. Ambiguity preservation: competing derivationをpacked hypergraphへ保持する。
6. Relation completeness: containment、dependency、binding、scope、control、effect、discourseを型付けする。
7. Generated provenance: implicit、macro、desugaring、recovery nodeへ生成ruleとlineageを付ける。
8. Incremental stability: unchanged regionのidentityを保持する。
9. Evidence binding: grammar、dictionary、compiler、model、backend、corpus revisionを固定する。
10. Projection survival: TaskContract、Program IR、Candidate、Outputまでobligationを追跡する。
11. Authority non-amplification: parse、geometry、modelからGrantを生成しない。
12. Budget totality: timeout、forest explosion、OOMをPartial + defectとして返す。

### 11. 非ユークリッド構文幾何

~~~text
SyntaxGeometry =
  H^h   hierarchy、nesting、taxonomy
  x E^e local token、sequence、short-range alignment
  x S^s recursion、cycle、repeated discourse
  x F^f forward/reverse非対称transition
  + GW  共通座標を持たないgraph間対応
~~~

| geometry | 用途 | 非主張 |
| --- | --- | --- |
| Hyperbolic | constituent hierarchy、nested scope | neighborは正しいparseではない |
| Euclidean | local token similarity | similarityは意味同値ではない |
| Spherical/cyclic | recursion、loop、return relation | cycle近接はcoreference確定ではない |
| Finsler | parse→lowering、forward/reverse cost | short geodesicはlosslessではない |
| Gromov-Wasserstein | CST、dependency、MRS、HIR間coupling | soft couplingはsource anchorではない |

geometry inputはsource-anchored relation、grammar production、verified edge、typed mask、revision receiptから作る。legacy TL値、LLM confidence、outputabilityから座標を作り、新TLとして戻すmetric launderingを禁止する。

曲率はversioned hypothesisである。Euclidean、hyperbolic、spherical、mixed-curvatureをholdout graphで比較し、distortion、neighbor recall、direction preservation、calibration driftを測る。

### 12. 離散と連続の相互的・段階的蒸留

~~~text
AnchoredDiscrete
  -> ContinuousProposed
  -> DiscreteDecoded
  -> VerifiedCandidate | RejectedResidual | NeedsEvidence | Incomparable
  -> BackflowApplied
  -> Converged | NextEpoch | CycleHold | BudgetHold
~~~

一epoch:

1. source spanとverified grammar edgeをDiscreteAnchorGraphへ固定する。
2. Unknown、Incomparable、NotApplicableをmask laneへ符号化する。
3. relation familyごとにmixed-curvature座標またはsoft couplingを構築する。
4. geometryがmissing edge、alternative parent、profile boundary、coreference、binding候補を提案する。
5. proposalをsource span、production、profile、direction、generation付きtyped objectへdecodeする。
6. grammar、feature unification、compiler、HPSG、semantic backendが独立検証する。
7. Passedは次epochのcandidate edgeとなる。
8. Failedはcounterexample付きresidualになる。
9. NeedsEvidence、Unavailable、Incomparableは保持する。
10. residualからneighbor、transport cost、search budgetを更新する。
11. discrete validatorを通ったedgeだけをcanonical forestへ入れる。
12. cycle digest再出現、budget exhaustion、backend failureをtyped terminationへ記録する。

geometryが提案しなかった既存derivationを自動削除しない。geometry residualはgrammar ruleをsession内で書き換えず、versioned calibration suggestionに限定する。

### 1. Final conclusion

TranslationLoss and DeepGrammar are not improved separately and connected later. They become one computation system:

~~~text
Unified Geometric DeepGrammar
  = lossless source substrate
  + unified syntax hypergraph
  + profile-specific semantic validators
  + mixed-curvature proposal geometry
  + discrete-continuous mutual distillation

Canonical TranslationLoss
  = source obligation
  + target correspondence
  + typed preservation defect
  + verifier receipt
  + recoverability and residual
~~~

Natural language and programs are not divided at the top level. English, Japanese, Rust, C/C++, TypeScript, mathematics, Markdown, SQL, shell, JSON, doc comments, and template literals share a substrate of source spans, token lattices, packed derivations, binding, scope, dependency, control, effect, and discourse relations.

Semantic acceptance remains separated. Program types, execution effects, ABIs, and undefined behavior must not share one validator with speech acts, ellipsis, coreference, and pragmatics. Source, syntax relations, candidates, geometry, and provenance are common; semantic validation is selected by GrammarProfile.

Non-Euclidean geometry is not a semantic truth machine. It proposes candidates for hierarchy, direction, cycles, and heterogeneous graph correspondence. Every continuous candidate returns to a discrete validator. A candidate without a receipt enters neither the canonical parse nor canonical TranslationLoss.

### 3. Origin of TranslationLoss and five symbolic-rigour regimes

Internal history locates explicit TranslationLoss in HTLF on 2026-02-28 as loss of structure, context, and qualia across representations. Initial values were qualitative estimates intended for later calibration. KCS extended it to design-to-code translation the next day.

The current five classifications are:

1. mathematics and logic
2. programs
3. natural language
4. creative artifacts
5. general actions

They are not loss components or fixed weights. They are multi-label **MeasurementRegimes** selecting obligations, admissible equivalence, validators, and abstention conditions.

| Regime | Primary preservation target | Primary validator |
| --- | --- | --- |
| mathematics / logic | axioms, quantification, proof obligations, countermodels | proof assistant, SMT, model checker |
| program | types, behavior, state transition, ABI, effects | compiler, tests, runtime, refinement |
| natural language | scope, modality, discourse, coreference, ambiguity | symbolic parser, semantic graph, NLI, human review |
| creative artifact | constraints, structure, intent, texture, plural acceptable results | constraint audit, pairwise review, provenance |
| general action | Authority, scope, state delta, causal result, reversibility | Authority kernel, execution receipt, state observation |

~~~text
ProjectionLoss      loss across representations
RealizationLoss     loss from plan to execution
OutcomeDeviation    difference between requested and observed outcomes
AuthorityViolation  permission-boundary violation; a hard gate, not a loss value
~~~

### 4. Initial integrated proposal

The initial proposal had three pillars:

1. Give natural language and programs one syntax substrate.
2. Embed syntax and meaning graphs in non-Euclidean spaces to explore relations beyond flat distances.
3. Alternate discrete forests and continuous geometry, sending high-loss areas to reparsing, other profiles, and other semantic views.

The direction remains. The adversarial audit rejects a single manifold, scalar loss, geometry-driven acceptance, and complete semantic identification of natural language with programs.

### 5. Postdoctoral adversarial audit

#### 5.1 Geometry does not define meaning

Embeddings compress supplied relations. If source relations are heuristic, curvature only launders heuristics into elegant coordinates. Geometry is limited to proposing correspondences.

#### 5.2 Ordinary Riemannian distance is symmetric

TranslationLoss is directional. Poincaré and ordinary Riemannian distance cannot alone express A→B versus B→A. Finsler geometry, directed quasi-distance, and typed forward/reverse witnesses are required.

#### 5.3 Some defects are not distances

Dropped, Contradicted, IntroducedWithoutSource, Unknown, and Incomparable are distinct states. A scalar can average away a critical defect.

#### 5.4 Natural language and programs do not share one semantics

They can share syntax relations, but programs have execution, types, effects, and environments while natural language has speech acts, pragmatics, and social context.

#### 5.5 CFG alone is insufficient

Agreement, long-distance dependency, ellipsis, typedefs, macros, and type-driven resolution require a typed constraint graph over the packed forest.

#### 5.6 The phrase complete parser overclaims

Correct understanding of every natural language, program, and context is not testable. Completeness is bounded to source totality, grammar-profile coverage, ambiguity retention, and backend revision.

#### 5.7 Mixed-document boundaries are ambiguous

Code fences, comments, strings, quotations, formulas, paths, and commands may fit several profiles. Use a Region/Dialect Lattice, not one hard classifier.

#### 5.8 Coordinates are non-identifiable

Rotation, reflection, isometry, and initialization alter coordinates. Raw coordinates are not evidence. Record revision-bound distortion, neighbor recall, and transport residuals.

#### 5.9 Curvature selection can itself be heuristic

Putting everything in hyperbolic space repeats Euclidean dogma. Separate sequences, trees, cycles, and directed relations in mixed-curvature products and require Euclidean ablations.

#### 5.10 Continuous feedback can self-confirm errors

If proposals teach the next epoch automatically, false clusters reinforce themselves. Only discretely and independently validated edges become anchors.

#### 5.11 Roundtrip is not sufficient for semantic equivalence

A closed but systematically wrong transformation can roundtrip. Independent views, counterexamples, compilers, runtime, and human review remain necessary.

#### 5.12 Gromov-Wasserstein coupling is not anchoring

Soft coupling proposes graph correspondence but proves neither one-to-one identity, causality, nor synonymy. Preserve mass leakage and many-to-many mappings.

#### 5.13 Calibration data defines the construct

Ambiguous labels cannot validate 0–100 values. Separate cohorts by regime, stage, direction, language, backend, and defect.

#### 5.14 Unknown is not maximum loss

Fail-closed execution policy and semantic magnitude are distinct. Preserve Unknown; close only risk-relevant actions.

#### 5.15 GPU cannot own semantics

Distances and transport parallelize well, but floating-point drift, device loss, and partial completion remain. Keep CPU references and discrete finalist validation.

#### 5.16 Authority contamination

Comments, quotes, fixtures, assistant summaries, and parser-inferred subjects must never create Grant. Only host-bounded user instruction spans can do so.

#### 5.17 Resource explosion

Scannerless parsing, SPPF, multiple profiles, mixed geometry, and GW need explicit forest, epoch, coupling, wall-time, and VRAM budgets.

#### 5.18 Evaluation leakage

Geometry selection, tuning, and final evaluation must not reuse one fixture set. Pin separate train, calibration, holdout, and adversarial revisions.

### 6. Final corrections from the audit

- Canonical ownership moves from geometry to Discrete Anchors plus Validator Receipts.
- TranslationLoss becomes ProjectionDefectGraph rather than a scalar.
- Geometry becomes a mixed-curvature proposal shadow.
- The Natural/Program binary split is removed while GrammarProfile semantics remain.
- Every discrete-continuous boundary gains a typed receipt.
- Accepted, rejected, NeedsEvidence, Unavailable, and Incomparable states all survive.
- Geometry residuals cannot update grammar or thresholds within a session.
- Any 0–100 view is cohort-specific empirical risk and advisory only.
- Source-span lineage continues through Program IR, Output, and Authority boundaries.

### 11. Non-Euclidean syntax geometry

~~~text
SyntaxGeometry =
  H^h   hierarchy, nesting, taxonomy
  x E^e local tokens, sequences, short-range alignment
  x S^s recursion, cycles, repeated discourse
  x F^f asymmetric forward/reverse transitions
  + GW  correspondence across graphs without shared coordinates
~~~

| Geometry | Use | Non-claim |
| --- | --- | --- |
| Hyperbolic | constituent hierarchy and nested scope | neighbor is not correct parse |
| Euclidean | local token similarity | similarity is not semantic equivalence |
| Spherical/cyclic | recursion, loops, and return relations | cyclic proximity does not settle coreference |
| Finsler | parse-to-lowering and forward/reverse cost | short geodesic is not lossless |
| Gromov-Wasserstein | coupling among CST, dependency, MRS, and HIR | soft coupling is not a source anchor |

Geometry input comes from source-anchored relations, grammar productions, verified edges, typed masks, and revision receipts. Building coordinates from legacy TL, LLM confidence, or outputability and returning them as new TL is forbidden metric laundering.

Curvature is a versioned hypothesis. Compare Euclidean, hyperbolic, spherical, and mixed-curvature models on holdout graphs using distortion, neighbor recall, direction preservation, and calibration drift.

### 12. Bidirectional staged discrete-continuous distillation

~~~text
AnchoredDiscrete
  -> ContinuousProposed
  -> DiscreteDecoded
  -> VerifiedCandidate | RejectedResidual | NeedsEvidence | Incomparable
  -> BackflowApplied
  -> Converged | NextEpoch | CycleHold | BudgetHold
~~~

One epoch:

1. Pin source spans and verified grammar edges in DiscreteAnchorGraph.
2. Encode Unknown, Incomparable, and NotApplicable in mask lanes.
3. Build mixed-curvature coordinates or soft couplings per relation family.
4. Propose missing edges, alternative parents, profile boundaries, coreference, and bindings.
5. Decode proposals with source spans, productions, profiles, direction, and generation.
6. Validate independently with grammar, feature unification, compiler, HPSG, and semantic backends.
7. Passed proposals become candidate edges.
8. Failed proposals become residuals with counterexamples.
9. Preserve NeedsEvidence, Unavailable, and Incomparable.
10. Update neighbors, transport costs, and budgets from residuals.
11. Admit only discretely validated edges to the canonical forest.
12. Record cycles, budget exhaustion, and backend failure as typed termination.

Never delete an existing derivation because geometry failed to propose it. Geometry residuals cannot rewrite grammar rules in-session.

### 15. GPU and performance boundary

GPU candidates:

- batched hyperbolic, Euclidean, and spherical distance
- Finsler directed costs
- Sinkhorn and Gromov-Wasserstein coupling
- candidate-edge scores
- forest-frontier SoA filters
- cross-view conflict matrices

CPU/discrete owners:

- UTF-8 and source-span validation
- grammar-production acceptance
- reference parser path
- feature unification, binding, and scope
- compiler/type/backend receipts
- ProjectionWitness, Authority, and OutputCommit

GPU output is a proposal receipt and creates no parse truth, Evidence provenance, Authority, or OutputCommit. Require scalar references, bounded finalist validation, device-loss quarantine, and epoch/lease/fence semantics.

### 16. Evidence, Authority, and failure semantics

- Malformed syntax returns Partial plus ParseDefect.
- Backend crash, timeout, and OOM return BackendUnavailable.
- Ambiguity is CompetingDerivations, not failure.
- No derivation is NoGrammarDerivation, not falsehood.
- Geometry coupling is ModelAdvisory-equivalent.
- Source-span, roundtrip, compiler, type-checker, runtime, and human-review evidence remain distinct.
- Comments, quotes, fixtures, assistant summaries, tool output, and parser inference create no Grant.
- Executable effects require a verified host-user instruction span and an independent Authority kernel.

### 17. Completion gates

Structural:

- 100% source byte/span coverage
- lossless roundtrip for whitespace, comments, quotes, code, formulas, and embedded dialects
- source spans for explicit nodes
- generation rule and lineage for implicit/generated nodes
- zero duplicate packed-derivation digests
- no collapse of Unknown, Unavailable, Incomparable, or ErrorRecovery
- stable identity in unchanged regions

Unified grammar:

- nested fixtures for code in prose, comments in code, template SQL, Markdown fences, and mathematics
- one UnifiedSyntaxHypergraph schema for natural language and programs
- no top-level Natural-versus-Program branch
- profile-specific validators preserve semantic differences

Geometry/distillation:

- paired Euclidean ablations
- preserved forward/reverse asymmetry
- zero direct promotion from geometry to canonical edges
- validator receipts for all accepted proposals
- retained rejected, NeedsEvidence, and Incomparable states
- fail-visible cycles, budgets, and device loss
- zero anchor loss across discrete-continuous-discrete roundtrips
- negative test against geometry built from legacy TL values

TL/integration:

- obligation-specific VerifierCapability
- one-to-many and many-to-one correspondence
- IntroducedWithoutSource retained as a defect
- witness chain from DeepGrammar through TaskContract, Program IR, Candidate, and Output
- zero Authority generation from parser or geometry
- separate calibration, holdout, and adversarial sets
- no promotion of benchmark pass to truth, proof, or human-level ability

### 21. Final judgment

The final design changes DeepGrammar from string heuristics into a Unified Grammar Compiler and TranslationLoss from fixed scalars into ProjectionDefectGraph. Mixed-curvature geometry and discrete-continuous mutual distillation connect them, but geometry receives no ownership of truth, Evidence, Authority, or commitment.

Natural language and programs share one syntax substrate. Semantic validators, execution effects, speech acts, and Authority remain separated. This is not integration by erasing differences; it is a common transformation substrate that preserves them.

The old substring heuristic, scalar TL, and Poincaré shadow are downgraded to legacy advisory and paired migration baselines. When the new route is Unavailable or Partial, the old route is never promoted to authoritative status.
