### 総合判定

添付レビューの中心命題は妥当である。v6.3.1の最大riskは型の不足ではなく、`VerifiedHostUser`、`HostBound`、`ValidatedObservation`、`Passed`、`Observed`、`HostBound closure`等の強い状態を、どのprincipalが生成できるかが構造的に閉じていないことである。

現行実装は、source roundtrip、候補非Authority、GPU fault quarantine、外部backendのUnavailable保持、RPAの依存順DAG等で良い基礎を持つ。しかし、公開field、公開enum、公開constructor、caller提供bool、形式だけ正しいdigestによって強い状態を構築できる面が複数存在する。そのため現在の正確な判定は次である。

| 面 | 判定 | 理由 |
|---|---|---|
| Translation Lossの問題設定 | 強く採用 | many-to-many、directionality、Unknown保持は有効 |
| ProjectionDefectGraph v2 | HardHold | stage/source-ledger/target revisionとverifier principalが閉じていない |
| Authority / Host | HardHold | verified host、authority event、output receiptがcaller-mintable |
| RPA architecture | 条件付き採用 | 40-stage DAGは有用だがHostBoundとClosedが真正でない |
| GPU execution基質 | 条件付き採用 | 実kernel/fault/readbackはあるがparity predicateが弱い |
| 256×8 world claim | HardHold | 2,048 slotは生成するがGPU入力は256 world labelだけ |
| TLDG local source release claim | HardHold | builtin self-validationとbool receiptでfalse closure可能 |
| Media adapter | 実験基質として採用 | method名、network、model/tool provenance、source-fragment bindingが不足 |
| mutual distillation | 未完成 |一回のAnchored→Validatedとreport-only backflow |
| v6.3.1 promotion | HardHold | P0 receipt/authenticity gateが未閉鎖 |

したがって、次の実装では機能familyを増やさず、最初にprincipal、attestation、revision、scope、nonce、subjectを型と検証器で閉じる。`Hash exists`、`enum says HostBound`、`bool=true`、`schema constant exists`は、いずれも真正性にならない。

### 追加で確認した重大な穴

添付レビューに加えて、次を確認した。

1. `AuthoritySourceKind::VerifiedHostUserSpan`と`AuthorityEvent`は公開値であり、`decide_authority()`へcallerが直接渡せる。`HostSeedEnvelope`だけをsealed化してもAuthorityは閉じない。
2. `ClosureWitness`、`ClosureLevel::HostBound`、`ReceiptOwner`も公開で、空blockerのHostBound witnessをcallerが作れる。
3. `HostSeedEnvelope`はfieldも公開で、`verified()`を使わず直接構築できる。
4. `HostOutputReceipt`のfieldは公開で、`append_durable_replay()`は`exact_binding=true`を主に信用する。hash chainは内容の一貫性を示してもissuer authenticityを示さない。
5. `bind_host_output()`は`candidate_digest`を`output_text`から再計算せず、caller値をreceiptへコピーする。candidate/output lineageが一致しないreceiptを作れる。
6. `CodexStopHookEvent`は入力originの暗号的・capability的証明を持たない。host process境界での受信そのものをprincipal evidenceへする必要がある。
7. `MediaSourceAuthority`は公開fieldで、`authorized=true`を直接構築してexecution routeへ渡せる。これはsource-rights gateの構造的bypassである。
8. `BackendDescriptor`、`GeometryGpuObservation`、`ExecutionReceipt`、`PromotionGate`も強いstateを公開fieldまたはcaller boolから表現できる。
9. RPAのv6.3.0 baseline boundは実`BaselineGuardReport`ではなく、公開された既知commit文字列のdigest比較である。既知定数を再送するだけでpredicateを満たせる。
10. `compare_lane_digests()`はcontext、binding、rows、mask、finalist、tie ruleを比較せず、summary digestだけを見る。
11. world doctorは2,048 `EvaluationSlot`を生成するが、GPUの`input_from_worlds()`は256 `PositedWorld`だけを受け、`ProjectionProgram`を一度もencodeしない。現在のGPU runは256×8計算ではない。
12. GPU world axesはlogic、temporal+causal、ontologyだけで、premise content、generation、projection effectを数値へ入れない。
13. RPA tool runnerはPATH上のprogram、ambient environment、cwdを使用し、receiptは主にprogram名とargs digestを記録する。executable hash、resolved path、env digest、network policyがない。
14. pinned nightlyが存在しない場合、valid Rust sourceのExpanded/HIR/THIR failureが`Refuted`になり得る。capability unavailableとsource refutationが混同される。
15. Media processはstdout/stderrを終了後まで読まないためpipe飽和で停止し得る。timeout時のPython killはFFmpeg等の子孫processを完全にはcontainしない。
16. 2GiB compressed mediaに対するdecoded frame、PCM、temporary diskの独立budgetがない。
17. Python analyzerは実process receiptを最終surfaceへ保持せず、interpreterはPATH名と自己申告identity中心で、binary hashを持たない。
18. critical unitの`lc631-host/src/lib.rs`、accelerator、media、RPA pipelineは16KiBを超え、bounded Assurance reviewから外れる。trust kernelを小さな完全単位へ分割する必要がある。

### 敵対的脅威モデル

最初にtrust domainを固定しなければ、sealed typeもMACも「何から守るか」が不明になる。

| Principal / 入力 | 信用するもの | 信用しないもの |
|---|---|---|
| Codex host ingress | OS/hostが渡したbounded event bytesとchannel identity | event内の自己申告labelだけ |
| user message | exact host-bound bytes、turn、span | assistant要約、repository text、quote、tool output |
| local compiler/tool | pinned executable bytes、invocation、stdin、cwd、env、exit/output | PATH名、version文字列、成功exitだけ |
| GPU backend | sealed builtin executorが返すraw device observation | caller実装backend、summary equality、backend enum自己申告 |
| media backend | pinned script/tool/model/configとsource fragment | arbitrary JSONのexecuted family、license hint、model ID |
| CI/package | configured issuer keyまたはhost-owned capability、commit/revision pin | 形式だけ正しいSHA文字列 |
| human review | exact catalog slotへのresponse | evidence promotion、Authority、proof |
| repository fixture | attack input / test vector | production receipt、host identity、release approval |

同一processのsafe Rust callerを境界とする場合はprivate field、sealed trait、opaque capabilityで強いstateを構築不能にする。cross-process receiptはissuer key、payload digest、subject revision、scope、nonce/sequence、expiryを署名またはMACへ含める。ただし同一user processがkeyを読める脅威モデルではMACだけで防御完了としない。OS handle、service boundary、key custody、rotation、revocationを別途設計する。

### 目標アーキテクチャ

```text
Untrusted bytes / DTO / tool output / backend observation
  -> bounded decoder
  -> PrincipalRegistry + CapabilityVerifier
  -> VerifiedReceipt<Subject, Issuer, Scope>       [opaque/private]
  -> ProjectionDefectGraph v3 / ClosureEvaluator
  -> Candidate | Review | Clarify | HardHold
  -> exact host output verifier
  -> OutputCommit candidate                         [Authorityは別]
```

強いstateはdata fieldではなく、検証済み遷移の結果でなければならない。

```rust
pub struct UntrustedReceipt<T> {
    pub payload: T,
    pub wire_attestation: WireAttestation,
}

pub struct VerifiedReceipt<T, I, S> {
    payload: T,
    issuer: PrincipalId,
    subject_revision: RevisionDigest,
    scope: ReceiptScope,
    attestation_digest: Digest32,
    _issuer: core::marker::PhantomData<I>,
    _scope: core::marker::PhantomData<S>,
    _seal: private::Seal,
}

pub trait ReceiptVerifier<T, I, S>: private::Sealed {
    fn verify(
        &self,
        input: UntrustedReceipt<T>,
        expected: &ExpectedSubject,
    ) -> Result<VerifiedReceipt<T, I, S>, VerifyError>;
}
```

verified typeをdeserializeしない。wire bytesは必ず`UntrustedReceipt`へdecodeし、current trust rootで再検証する。verified receiptをJSONへserializeする場合も、consumerは再びuntrusted wireとして受け取る。

### GPU・world閉鎖設計

現行summaryはtelemetryとして保持できるがcorrectness certificateから外す。添付例`[0,0,2,1]`と`[0,1,0,2]`はlen/min/max/sum/xor/weighted/zero countが同一で、finalist orderingが異なる。したがってsummary digest equalityはdecision parityでない。

2,048 row程度のprojection scoreは全readbackしても小さい。関係matrix全体を戻す必要はない。まず次を比較する。

- exact projection scoreとmask、またはblock lower-bound certificate
- finalist ID、score、mask、tie key、cutoff margin
- CPUで再計算したfinalistとcutoff近傍
- context digest、RevisionBinding digest、lane schema、row count
- mask category countとmask-specific selection rule
- selected relation submatrixまたはper-block dominance bound

GPUがtop-kだけを返す場合、CPUは「返されなかったrowにより良い候補がない」ことを検証できるblock boundを必要とする。これがない場合はprojection score全readbackを選ぶ。性能よりcorrectness contractを先に決める。

`NumericMask`は数値sentinelへ潰さない。値bufferとmask bufferを最後まで分け、relationは少なくともKnownDominates、KnownEqual、KnownNonDominated、Unknown、NotApplicable、Incomparableを区別する。`ProjectionLoss`はcanonical TLでないため`ProjectionPriorityScalar`へ改名する。`WorldContradiction`は`WorldNonDominance`へ改名し、本物のContradictionはtyped logical/constraint witnessだけから生成する。

256×8を実装事実にするには、`EvaluationSlot`を実入力へ変える。

```text
PositedWorld + ProjectionProgramIR
  -> EffectivePremiseIR
  -> applicability / axiom delta / causal-temporal effect
  -> semantic feature row + mask + provenance
  -> 2,048 evaluation rows
  -> GPU proposal
  -> CPU decision-sufficient validation
```

`ProjectionProgram`はlabelでなくprecondition、effect、counterexample obligation、expected loss、residualを持つProgram IRにする。premise digestやgenerationはcontext hashだけでなく、effective semantic featuresとreceipt subjectへbindする。

### RPA・tool execution閉鎖設計

RPAはEvidenceStateとClosureStateを分ける。

```rust
pub enum EvidenceState {
    Observed,
    Candidate,
    NeedsEvidence,
    Unavailable,
    Refuted,
}

pub enum ClosureState {
    Open,
    Satisfied,
    NotApplicable(VerifiedReceipt<NotApplicableEvidence, VerifierPrincipal, StageScope>),
    Refuted,
}
```

`Observed`かつblocking residualありはOpenである。`blockers`を`blocking_residuals`と`claim_notes`へ分け、releaseは全requested stageの`Satisfied`だけを受ける。HostBoundはwire enumから削除するかlegacy DTOに限定し、verified principal receiptなしではclosureへ変換しない。

ToolExecutionReceiptにはresolved executable path、executable SHA-256、toolchain identity、stdin digest、argv digest、cwd digest、sanitized env digest、network policy、timeout/output budget、exit status、stdout/stderr digest、truncation、process-tree containmentを含める。PATH shadowing、`RUSTC_WRAPPER`、Cargo config、proxy、Python startup、locale、timezoneを明示する。missing pinned nightlyはUnavailableでありvalid sourceのRefutedではない。

v6.3.0 baselineは既知定数digestでなく、`BaselineGuardReport`のexact protected-set revisionとhost/CI issuerをbindしたverified compatibility receiptをRPAへ渡す。packageとremote CIもdigest文字列ではなく、commit、workflow/run、artifact digest、issuerを持つreceiptにする。

### Media閉鎖設計

MediaSourceAuthorityはopaque verified capabilityにする。execution APIはcaller構築可能なbool authorityを受けず、source file handle/snapshot、rights scope、network policy、source digestをbindした`VerifiedMediaSource`を受ける。

実method名は観測処理へ合わせる。

| 現行family claim | 実処理 | 修正後method |
|---|---|---|
| ObjectDetection | OpenCV HOG people detector / Haar face region | `PersonBoxHog` / `FaceRegionHaar` |
| ShotBoundary | color-histogram distance | `HistogramShotCandidate` |
| ActionRecognition | frame absdiffの存在 | `FrameMotionHeuristic` |
| Diarization | 1秒windowの2-cluster音響特徴 | `AnonymousAcousticClusterHeuristic` |
| CrossModalAlignment | transcriptとframeの共存 | `AudioVideoCoPresence` |
| ASR | faster-whisper tiny.en | pinned local-model ASR method receipt |

family catalogは将来capabilityとして残せるが、exact method receiptがfamily contractを満たすまでExecuted/Validatedへしない。Python scriptが返す`executed_families`はuntrusted claimであり、Rust側validatorがobservation kind、method、binary/model/config receiptから再構成する。

ASRにはresolved local model directoryとexpected model manifest digestを渡し、model ID downloadを禁止する。`HF_HUB_OFFLINE`等のlibrary flagだけでなくprocess-level network denyを要求する。Python、backend script、FFmpeg/ffprobe、model、package lock、config、sourceのhashをRust側で計算する。stdout/stderrを並行drainし、Windows Job Objectまたは同等process groupでdescendantをcontainする。compressed input、decoded frames、PCM、temporary disk、observation countへ別budgetを置く。

各observation digestはsource media、decoded fragment、timestamp、backend/tool/model/config、candidate payloadをbindする。ASRは`AudioToTranscript`、visionは`FrameToObservation`、event化は`ObservationToEvent`のProjectionEdge v3を生成し、Media独自の単なる文字列digestで閉じない。

### Additional critical findings

Beyond the attached review, this audit confirmed:

1. `AuthoritySourceKind::VerifiedHostUserSpan` and `AuthorityEvent` are public values that callers may directly pass into `decide_authority()`. Sealing only HostSeed does not close Authority.
2. `ClosureWitness`, `ClosureLevel::HostBound`, and `ReceiptOwner` are public; callers can construct a HostBound witness with no blockers.
3. `HostSeedEnvelope` fields are public and allow direct construction without `verified()`.
4. `HostOutputReceipt` fields are public, while `append_durable_replay()` primarily trusts `exact_binding=true`. A hash chain establishes consistency, not issuer authenticity.
5. `bind_host_output()` does not recompute `candidate_digest` from `output_text`; it copies the caller value into the receipt, permitting inconsistent candidate/output lineage.
6. `CodexStopHookEvent` has no cryptographic or capability proof of input origin. Receipt identity must include the host process ingress boundary.
7. `MediaSourceAuthority` has public fields, so callers may directly construct `authorized=true` and bypass the source-rights gate.
8. `BackendDescriptor`, `GeometryGpuObservation`, `ExecutionReceipt`, and `PromotionGate` also expose strong states through public fields or caller booleans.
9. The RPA v6.3.0 baseline predicate compares a known commit-string digest rather than accepting a verified `BaselineGuardReport`. Replaying the public constant satisfies it.
10. `compare_lane_digests()` ignores context, binding, rows, masks, finalists, and tie rules and compares summary digests only.
11. The world doctor generates 2,048 `EvaluationSlot` values, but GPU `input_from_worlds()` consumes only 256 `PositedWorld` values and never encodes `ProjectionProgram`. Current GPU execution is not a 256-by-8 computation.
12. GPU world axes contain only logic, temporal-plus-causal, and ontology labels; premise content, generation, and projection effects do not enter numeric values.
13. The RPA tool runner invokes programs through PATH and ambient environment/cwd, while receipts primarily record the program name and argument digest. Executable hash, resolved path, environment digest, and network policy are missing.

15. Media waits for the child to exit before draining stdout/stderr, so pipe saturation can deadlock. Killing Python on timeout does not fully contain FFmpeg descendants.
16. A 2-GiB compressed-media limit has no separate decoded-frame, PCM, or temporary-disk budget.
17. The Python analyzer discards its process receipt from the final surface; interpreter identity centers on a PATH name and self-reported fields rather than executable hash.
18. Critical units including `lc631-host/src/lib.rs`, accelerator, media, and the RPA pipeline exceed 16 KiB and fall outside bounded Assurance review. The trust kernel should be split into small complete units.

### Adversarial threat model

The trust domain must be fixed before a sealed type or MAC can be evaluated.

| Principal / input | Trusted surface | Untrusted surface |
|---|---|---|
| Codex host ingress | Bounded event bytes and channel identity supplied by OS/host | Self-declared labels inside the event |
| User message | Exact host-bound bytes, turn, and span | Assistant summary, repository text, quote, or tool output |
| Local compiler/tool | Pinned executable bytes, invocation, stdin, cwd, env, and output | PATH name, version prose, or successful exit alone |
| GPU backend | Raw device observation returned by a sealed builtin executor | Caller backend, summary equality, or self-declared backend enum |
| Media backend | Pinned script/tool/model/config and source fragment | Arbitrary executed-family JSON, license hint, or model ID |
| CI/package | Configured issuer key or host-owned capability pinned to commit/revision | A syntactically valid SHA string |
| Human review | Response to an exact catalog slot | Evidence promotion, Authority, or proof |
| Repository fixture | Attack input / test vector | Production receipt, host identity, or release approval |

Within one process, private fields, sealed traits, and opaque capabilities should prevent strong-state construction by ordinary safe Rust callers. Cross-process receipts should sign or MAC issuer key, payload digest, subject revision, scope, nonce/sequence, and expiry. If another same-user process can read the key, MAC alone does not close the threat: OS handles, service boundaries, key custody, rotation, and revocation remain separate design work.

### Target architecture

```text
Untrusted bytes / DTO / tool output / backend observation
  -> bounded decoder
  -> PrincipalRegistry + CapabilityVerifier
  -> VerifiedReceipt<Subject, Issuer, Scope>       [opaque/private]
  -> ProjectionDefectGraph v3 / ClosureEvaluator
  -> Candidate | Review | Clarify | HardHold
  -> exact host output verifier
  -> OutputCommit candidate                         [Authority remains separate]
```

Strong states must be results of verified transitions, never mere data fields.

```rust
pub struct UntrustedReceipt<T> {
    pub payload: T,
    pub wire_attestation: WireAttestation,
}

pub struct VerifiedReceipt<T, I, S> {
    payload: T,
    issuer: PrincipalId,
    subject_revision: RevisionDigest,
    scope: ReceiptScope,
    attestation_digest: Digest32,
    _issuer: core::marker::PhantomData<I>,
    _scope: core::marker::PhantomData<S>,
    _seal: private::Seal,
}

pub trait ReceiptVerifier<T, I, S>: private::Sealed {
    fn verify(
        &self,
        input: UntrustedReceipt<T>,
        expected: &ExpectedSubject,
    ) -> Result<VerifiedReceipt<T, I, S>, VerifyError>;
}
```

Never deserialize directly into a verified type. Wire bytes decode into `UntrustedReceipt` and must be reverified against the current trust root. Even a serialized verified receipt becomes untrusted wire at the consumer boundary.

ProjectionDefectGraph v3 should include at least:

pub struct ProjectionEdgeV3 {

    pub source_anchors: Vec<SourceAnchorV3>,

`IntroducedWithoutSource` uses `source_anchors=[]` plus an independent `TargetClaimId`. A Must-obligation commit candidate requires edges for every TaskContract stage path, or a verified NotApplicable receipt.

### GPU and world closure design

Current summaries may remain telemetry but must leave the correctness certificate. The attachment’s `[0,0,2,1]` and `[0,1,0,2]` example has equal length/min/max/sum/xor/weighted/zero-count summaries but different finalist ordering. Summary equality is therefore not decision parity.

Reading back 2,048 projection scores is small enough; a full relation matrix is unnecessary. Compare at least:

- exact projection score and mask, or a block lower-bound certificate;
- finalist ID, score, mask, tie key, and cutoff margin;
- CPU-recomputed finalists and cutoff neighbors;
- context digest, RevisionBinding digest, lane schema, and row count;
- mask-category counts and mask-specific selection rules;
- selected relation submatrix or per-block dominance bounds.

If GPU returns top-k only, CPU needs a verifiable block bound proving that no omitted row is better. Without such a bound, read back all projection scores. Correctness contract precedes performance.

Never collapse `NumericMask` into a numeric sentinel. Keep value and mask buffers separate and distinguish at least KnownDominates, KnownEqual, KnownNonDominated, Unknown, NotApplicable, and Incomparable. Rename `ProjectionLoss` to `ProjectionPriorityScalar`, because it is not canonical TL. Rename `WorldContradiction` to `WorldNonDominance`; only typed logical/constraint witnesses may create actual Contradiction.

Making 256 by 8 an implemented fact requires `EvaluationSlot` to become real input:

```text
PositedWorld + ProjectionProgramIR
  -> EffectivePremiseIR
  -> applicability / axiom delta / causal-temporal effect
  -> semantic feature row + mask + provenance
  -> 2,048 evaluation rows
  -> GPU proposal
  -> CPU decision-sufficient validation
```

`ProjectionProgram` must become Program IR with preconditions, effects, counterexample obligations, expected loss, and residuals. Premise digest and generation bind both the receipt subject and effective semantic features, not the context hash alone.

### RPA and tool-execution closure design

RPA separates EvidenceState from ClosureState:

```rust
pub enum EvidenceState {
    Observed,
    Candidate,
    NeedsEvidence,
    Unavailable,
    Refuted,
}

pub enum ClosureState {
    Open,
    Satisfied,
    NotApplicable(VerifiedReceipt<NotApplicableEvidence, VerifierPrincipal, StageScope>),
    Refuted,
}
```

Observed with a blocking residual remains Open. Split `blockers` into `blocking_residuals` and `claim_notes`; release accepts only Satisfied requested stages. Remove HostBound from production wire or confine it to a legacy DTO that cannot enter the new gate without a verified principal receipt.

ToolExecutionReceipt records resolved executable path, executable SHA-256, toolchain identity, stdin digest, argv digest, cwd digest, sanitized-environment digest, network policy, timeout/output budget, exit status, stdout/stderr digest, truncation, and process-tree containment. Explicitly account for PATH shadowing, `RUSTC_WRAPPER`, Cargo config, proxy settings, Python startup, locale, and timezone. A missing pinned nightly is Unavailable, never source Refutation.

The v6.3.0 baseline must arrive as a verified compatibility receipt binding the exact protected-set revision and host/CI issuer, not a known constant digest. Package and remote-CI receipts bind commit, workflow/run, artifact digest, and issuer.

Make MediaSourceAuthority an opaque verified capability. Execution accepts a `VerifiedMediaSource` binding a source file handle/snapshot, rights scope, network policy, and source digest—not a caller-constructible Boolean authority.

### ResidualRiskLedger and completion definition

Even after ARC631-24, never auto-close:

- a cross-process attacker that can read key material under the same user authority;
- host-receipt authenticity after OS/host compromise;
- correctness of compilers, GPU drivers, FFmpeg, Python runtimes, or model implementations;
- accuracy and coverage of external parser/semantic backends;
- unsupported syntax and unexplored inputs in Miri/fuzz/formal tools;
- truth of media identity, emotion, intent, or mental-state claims;
- GPU hardware occupancy or general performance superiority;
- completeness across every repository path, platform, and legacy consumer;
- exact remote-client delivery.
